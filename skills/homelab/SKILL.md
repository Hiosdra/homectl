---
name: homelab
description: Operate inventory machines through homectl using existing users, credential injection and access tiers. Use for homelab inspection, troubleshooting, software updates or service restarts.
---

1. Run `homectl hosts --json`, then `homectl inspect <host> --json`. Resolve ambiguous names with the user. Read description, caution, transport, auth reference, access and enforcement. Never substitute a more permissive host.
2. Use `homectl exec <host> --json -- <executable> <separate argv...>` for operations. Quote each argument as needed for the local shell. The SSH alias and local transport are managed by homectl. Use `sudo -n` only on full, or the exact absolute argv from sudo_allow on sudo-approved. Do not obtain sudo credentials on user/observe. Use existing accounts.
3. Inspect before changing, and verify afterwards. For an idle printer, a requested update can use `sudo -n apt update`, `sudo -n apt full-upgrade -y`, then `systemctl is-active klipper moonraker`. Read machine cautions before restarting a printer.
4. Treat **every destructive operation as requiring explicit human confirmation**, including on full. This includes deleting files, VMs, containers, volumes, backups, databases, users or snapshots, formatting/partitioning, resetting/replacing configuration, and removals that lose data. Broad requests to fix/update/clean do not count. Neither native automatic approval nor a permissive access tier counts as explicit confirmation.
5. Before destruction, run the exact command with `--dry-run --impact '<concrete objects/devices/files, scope and consequence>'` and show host, argv, affected targets and consequence to the user. Resolve wildcards/recursive targets first; never describe a target as “old stuff”. Wait for the user's approval of that exact operation. The plan returns an approval digest. Only after explicit confirmation, run the unchanged host/argv/impact with `--approval <digest>`. Never calculate, copy or invent the approval to bypass asking. Unknown/opaque commands also require reviewing exact effects.
6. If native approval clearly shows the concrete destructive command, target and impact and the human approves it, pass the digest in that same invocation. This counts once; do not ask another chat confirmation. If the UI cannot show those details, ask in chat first. Stop when required approval is unavailable. A changed target, command, inventory or impact invalidates approval.
7. Keep secret values outside model context. Never use `aac connect --output json`, `bw get`, `env`, `printenv`, shell tracing, secret-literal flags or direct private-key reads. Let homectl launch the private credential worker. Pair/unlock only through the user's trusted terminal/provider. Do not call the askpass helper directly. Do not print config files or logs known to contain credentials; redact at the source.
8. Respect policy errors instead of bypassing with raw SSH/local shell. Full permits arbitrary commands; the classifier is a workflow gate, not a sandbox. System enforcement comes from Unix accounts, actual sudoers and provider ACLs. `enforcement: sudoers` is a declared administrator configuration, not proof that all other sudo rules were removed.
9. Do not delete temporary files automatically: deletion follows the same explicit-confirmation rule. Do not create new Codex/Claude instances on managed hosts. Commands and credentials stay on the agent host; remote control clients only approve/control the session.

Run `homectl doctor <host> --json` on authentication failures. Exit 4 means confirmation is required; 3 means policy/conflict; 5 transport/provider; 6 remote command failure. Never retry a potentially destructive operation without assessing whether it already took effect.
